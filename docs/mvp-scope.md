# MVP Scope — AI Gift Assistant

## 1. Определение MVP

В состав MVP входят основные пользовательские сценарии (UC1–UC9), определённые ранее:

1. Регистрация и вход в систему
2. Просмотр истории запросов
3. Управление профилем
4. Запрос рекомендаций подарков (текстовый ввод, контекстная форма)
5. Исключение нежелательных вариантов и повторное уточнение
6. Выбор подходящего подарка из предложенных
7. Добавление подарков в избранное
8. Работа с чатами (создание, просмотр, поиск)
9. Напоминания (создание, редактирование, просмотр)

**Итог:**  
Все ключевые use-cases реализованы.  
Сквозной сценарий работает:  
_пользователь → ввод запроса → обработка AI → получение результата → история/избранное_.

## 2. Приоритизация backlog

Так как MVP завершён, текущий backlog состоит из задач по качеству, безопасности и масштабированию.

### Основные направления:

- **Безопасность**

  - хэширование паролей (bcrypt),
  - корректная работа JWT,
  - обновление механизмов хранения токенов.

- **Автоматизация**

  - автоматические тесты,
  - настройка CI/CD (GitHub Actions),
  - статический анализ и линтинг.

- **Производительность**

  - ускорение API-ответов,
  - кэширование,
  - оптимизация запросов к БД,
  - оптимизация вызовов AI.

- **Улучшение UX**
  - обновлённые состояния загрузки,
  - улучшенная логика работы с чатами, историей и избранным,
  - оптимизация интерфейса под мобильные устройства.

## 3. Планирование следующего спринта

Так как текущий спринт завершает MVP, в следующем спринте планируются улучшения, закрывающие риски выхода в продакшен.

### Задачи следующего спринта:

- Внедрение хэширования паролей (bcrypt).
- Переработка аутентификации:
  - корректные JWT-токены,
  - сроки годности,
  - обновление токена.
- Настройка CI/CD пайплайна:
  - сборка и деплой,
  - автоматические тесты,
  - проверка стиля кода.
- Добавление базовых тестов:
  - аутентификация,
  - поиск,
  - рекомендации,
  - избранное.
- Оптимизация времени отклика API:
  - уменьшение количества обращений к БД,
  - кэширование в Redis,
  - оптимизация промптов.

---

## 4. Управление техническим долгом

На текущий момент выявлены следующие критичные зоны:

- **Отсутствие автоматических тестов** — повышает вероятность регрессий.
- **Нет CI/CD** — весь пайплайн работает вручную.
- **Производительность ограничена** — при большом кол-ве одновременных запросах возможны задержки.
- **Неполное покрытие use-cases интеграционными тестами**.

## Вывод

MVP успешно реализован.  
Все ключевые пользовательские сценарии работают и подтверждены прототипом.

- расширить тестирование и мониторинг.
