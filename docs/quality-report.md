## 2. Quality Gates

**Quality Gates** — набор правил, через которые должно проходить каждое изменение в проекте.

### Текущее состояние

- ❌ **Нет автоматических тестов**
- ❌ **CI/CD пайплайн не настроен**
- ❌ **Нет проверки зависимостей**
- ❌ **Нет анализа покрытия тестами**
- ✅ **Код проверяется вручную**
- ✅ **Linting частично применяется**
- ✅ **Проект структурирован, маршруты и слои разделены**

### План улучшений

1. **Unit-тесты**

   - регистрация
   - авторизация
   - создание чата
   - генерация рекомендаций

2. **Интеграционные тесты**

   - e2e сценарий: _запрос рекомендаций → напоминание_

3. **Покрытие тестами**

   - цель: **≥ 70% основных UC**

4. **Настройка CI/CD (GitHub Actions)**

   - запуск тестов
   - проверка линтера
   - проверка безопасности зависимостей
   - автодеплой на Staging

5. **Security checks**
   - проверка .env
   - проверка токенов
   - зависимостей через `npm audit`

## 4. Security Audit (базовый аудит)

### Текущее состояние

- ❌ **Пароли пока не хэшируются (plain text)**
- ❌ **Нет защиты от brute-force**
- ❌ **Нет мониторинга попыток входа**
- ❌ **Нет rate limiting**
- ⚠️ **Секреты хранятся в .env, но не зашифрованы**
- ✅ **CORS настроен**
- ✅ **JWT используется**
- ✅ **HTTPS планируется для продакшена**

### Основные риски

1. **Brute-force атаки без ограничений по входу**
2. **Опасность утечки .env файла**
3. **Нет логирования попыток взлома**

### План устранения рисков

- Добавить rate limiting (например, `express-rate-limit`)
- Ограничить доступ к .env
